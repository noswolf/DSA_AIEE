Module 0: Tree Data Structures & Theory

A Tree is a non-linear, hierarchical data structure simulating a tree structure with a root value and subtrees of children with parent nodes. It is defined recursively and underpins modern filesystems, databases, compilers, and searching algorithms.

Hierarchical Recursive Definition Non-Linear O(log N) Potential

Core Terminology

  • Root: The topmost node in a tree; it has no incoming edges / parent.
  • Edge: The connecting link / pointer from a parent node to a child node.
  • Child: A node directly descended from and connected below another node.
  • Parent: The immediate ancestor node directly above a child node.
  • Leaf: A node with no children (degree = 0).
  • Subtree: A complete tree formed by any node and all of its descendants.

Measurements & Properties

  • Degree: The number of subtrees (children) attached to a given node.
  • Depth: The number of edges from the Root down to the node (Root depth = 0).
  • Height: The number of edges on the longest path from the node down to a leaf (Leaf height = 0).
  • Path: A sequence of consecutive nodes and edges connecting two nodes.
  • Tree Size: The total number of nodes $N$ contained in the tree.

Anatomy of a Binary Tree

Binary Tree Definition & Properties

A Binary Tree is a tree where each node has at most two children, conventionally called the left child and right child.

  • Max Nodes / Level: Level $k$ can hold at most $2^k$ nodes.
  • Max Total Nodes: A binary tree of height $h$ can hold at most $2^{h+1} - 1$ nodes.
  • Minimum Height: A tree with $N$ nodes has height at least $\lfloor \log_2 N \rfloor$.

Types of Trees

  • Full Tree: Every node has either 0 or 2 children.
  • Complete Tree: All levels are filled except possibly the last, which is filled left-to-right.
  • Perfect Tree: All internal nodes have 2 children and all leaves are at the same depth.
  • Balanced Tree: Left and right subtree heights differ by at most 1 for every node.
  • Degenerate Tree: Each node has only one child, behaving like a linked list.

Real-World Applications of Tree Data Structures

File Systems Directories and nested files in Windows (NTFS), macOS (APFS), and Linux (ext4) form an N-ary tree.
DOM (Document Object Model) Web browsers parse HTML files into an interactive DOM tree where each HTML tag is an element node.
Compilers & AST Abstract Syntax Trees (AST) represent code grammar and syntax during Python compilation & execution.
Routing & Spanning Trees Network protocols (like Spanning Tree Protocol - STP) prevent bridge loops and find optimal network routes.

Module 1: Tree Traversals (DFS & BFS)

Tree Traversal is the process of visiting every single node in a tree exactly once in a predictable, systematic order. Unlike linear arrays, trees can be traversed in multiple dimensions: Depth-First Search (DFS) and Breadth-First Search (BFS).

Depth-First Search (DFS)

Explores as deep as possible along each branch before backtracking. Uses a Stack (naturally via the Python recursion call stack).

1. Pre-order: Root → Left → Right (Process current node first)
2. In-order: Left → Root → Right (Visits in sorted order in BSTs)
3. Post-order: Left → Right → Root (Visits children before root)

Breadth-First Search (BFS)

Also known as Level-Order Traversal. Visits all nodes at the current depth level before moving on to the next level down. Uses a Queue (FIFO).

Level Order Traversal Algorithm: 1. Enqueue the root node.
2. While Queue is not empty: Dequeue node $u$, process $u$, then Enqueue $u$'s left child and right child.

Python Implementations of the 4 Core Traversals

Pre-Order (Root, L, R) O(N)
def pre_order(root): if root is None: return print(root.val) # Root pre_order(root.left) # Left pre_order(root.right)# Right

Use: Tree copying, expression prefix serialization.

In-Order (L, Root, R) O(N)
def in_order(root): if root is None: return in_order(root.left) # Left print(root.val) # Root in_order(root.right) # Right

Use: Yields strictly sorted keys on a BST!

Post-Order (L, R, Root) O(N)
def post_order(root): if root is None: return post_order(root.left) # Left post_order(root.right)# Right print(root.val) # Root

Use: Deleting trees, bottom-up calculations (height).

Level-Order (BFS) O(N)
from collections import deque def level_order(root): if not root: return q = deque([root]) while q: node = q.popleft() print(node.val) if node.left: q.append(node.left) if node.right: q.append(node.right)

Use: Shortest paths, level-by-level printouts.

Traversal Summary Comparison

Traversal Order Pattern Data Structure Time Complexity Space Complexity Primary Use Case
Pre-order (DFS) Root → Left → Right Call Stack / LIFO O(N) O(H) Cloning tree, serialization
In-order (DFS) Left → Root → Right Call Stack / LIFO O(N) O(H) Sorted elements in BST
Post-order (DFS) Left → Right → Root Call Stack / LIFO O(N) O(H) Tree deletion, bottom-up tree DP
Level-order (BFS) Level 0 → Level 1 → ... Queue / FIFO O(N) O(W) (Max width) Shortest path, layer rendering

Module 3: Binary Search Tree (BST) Fundamentals

A Binary Search Tree (BST) is a specialized binary tree with a strict ordering property enabling fast binary search, dynamic insertions, and deletions in O(log N) average time.

The Invariant BST Ordering Rule

For every node in a Binary Search Tree with key $K$:

1. Left Subtree Invariant All keys in the left subtree must be strictly less than $K$ (key < K).
2. Right Subtree Invariant All keys in the right subtree must be strictly greater than $K$ (key > K).
3. No Duplicate Keys & Recursive Each key is unique. Both the left and right subtrees must themselves be valid BSTs.

Python BSTNode Implementation

Each BST node holds a key (ordering value), an optional value (payload), and two child pointers (left and right).

class BSTNode: def __init__(self, key, value=None): self.key = key # Sorting & comparison key self.value = value # Satellite data payload self.left = None # Pointer to Left Child (key < self.key) self.right = None # Pointer to Right Child (key > self.key) self.parent = None # Optional parent reference

BST vs Array vs Linked List Complexity

Operation Sorted Array Linked List BST (Avg Case) BST (Worst Skewed)
Search O(log N) O(N) O(log N) O(N)
Insert O(N) (shift) O(1) (at head) O(log N) O(N)
Delete O(N) (shift) O(N) (search) O(log N) O(N)
Min / Max O(1) O(N) O(log N) O(N)

* Note: If elements are inserted in ascending order, a standard BST degenerates into a linear linked list (Skewed Tree, $O(N)$). Self-balancing trees (AVL, Red-Black) guarantee $O(\log N)$.

BST vs Regular Binary Tree

Feature Regular Binary Tree Binary Search Tree
Ordering Rule No required ordering Left < Node < Right
Search Strategy May require checking many nodes Can discard one subtree per comparison
Typical Search O(N) O(log N) average
Main Use General hierarchy / expression structure Dynamic sorted set / fast lookup

Why Use a BST?

A BST is useful when data arrives dynamically and you need both sorted order and fast lookup without rebuilding the whole structure.

  • Supports dynamic insert and delete while preserving sorted order.
  • In-order traversal produces keys in ascending sorted order.
  • Foundation for balanced search trees such as AVL and Red-Black trees.

Module 4: BST Operations (Search, Insert, Delete)

Every operation in a BST exploits the ordering invariant: at each step we compare the target key with the current node, eliminating half of the remaining tree in each decision step.

1. Search, FindMin & FindMax Operations

def search(root, target): if root is None: # Base Case 1: Target Not Found return None if root.key == target: # Base Case 2: Target Found! return root if target < root.key: # Target is smaller -> go left return search(root.left, target) else: # Target is larger -> go right return search(root.right, target)
def find_min(root): if root.left is None: # Leftmost node is minimum return root return find_min(root.left) def find_max(root): if root.right is None: # Rightmost node is maximum return root return find_max(root.right)

Logic: Because smaller values are always left, the minimum key is found by traversing left repeatedly until node.left is None.

2. Insert Operation

def insert(root, key): if root is None: # Found empty leaf position return BSTNode(key) # Create node & link back up if key < root.key: # Recurse left subtree root.left = insert(root.left, key) elif key > root.key: # Recurse right subtree root.right = insert(root.right, key) # If key == root.key, duplicate ignored return root # Return root to preserve links
How BST Insertion Works:
  1. Start from the Root and compare key with root.key.
  2. If smaller, descend to left; if greater, descend to right.
  3. When hitting an empty spot (None), allocate new BSTNode(key).
  4. Rewire parent's left/right pointer to the new node as the call stack unwinds.

3. Delete Operation (Handling the 3 Structural Cases)

Deletion is the most intricate BST operation because removing a node must preserve the BST ordering property without disconnecting children.

Case 0: Leaf Node (0 Children) Simply delete the node and replace it with None.
Case 1: 1 Child (Left or Right) Bypass the deleted node by returning its non-null child directly to its parent.
Case 2: 2 Children (Complex) Find the In-Order Successor (minimum node in right subtree), copy its key, and recursively delete the successor.
def delete(root, key): if root is None: return None if key < root.key: root.left = delete(root.left, key) elif key > root.key: root.right = delete(root.right, key) else: # Found target node to delete! # Case 0: No children if root.left is None and root.right is None: return None # Case 1: One child (only right child) elif root.left is None: return root.right # Case 1: One child (only left child) elif root.right is None: return root.left # Case 2: Two children else: temp = find_min(root.right) # 1. In-order successor (min of right subtree) root.key = temp.key # 2. Copy successor key to current node root.right = delete(root.right, temp.key) # 3. Recursively delete successor node return root
